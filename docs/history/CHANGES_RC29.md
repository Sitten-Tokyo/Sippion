# RC29 completeness and cache-privacy hardening (historical record)

- Bumped package version to `0.1.0-rc.29`.
- Separated policy exclusion from adaptive-scan incompleteness without treating policy-excluded files as inspected repository content.
- A zero-hit search with one or more `policy_excluded` files now receives bounded confidence (`0.350`) rather than complete-no-match confidence (`0.980`).
- `repo_context` now emits `NO_MATCH_IN_SEARCHABLE_SET` instead of absolute `NO_MATCH` when policy-excluded files were not inspected. If hits exist, it emits `CONTEXT_FROM_SEARCHABLE_SET` so the model-visible result does not imply full-repository completeness.
- Policy exclusions remain non-expandable, so oversized/stable-non-UTF8/Unix-or-Windows-hard-linked files do not reintroduce the RC26-style 32 → 512 MiB futile adaptive retry loop.
- Replaced cached `RepoMapSymbol` values with structural-only cached symbols containing only `name`, `kind`, and `line`.
- Shared analysis caches no longer retain source-line `signature` strings. Signatures used for ranking/output are reconstructed per call from the freshly verified and high-confidence-secret-redacted source.
- Completion bonus in retrieval confidence is withheld whenever policy-excluded files exist.
- Added regression coverage for policy-excluded confidence/status and for absence of source-line signature text from the shared analysis cache.
- Post-review hardening: unquoted high-confidence secret literals now redact URL/password punctuation (including `:`, `@`, `!`, and `#`) without treating obvious computed expressions as literals.
- Post-review hardening: assignment separator parsing now prefers an earlier `=` over colons inside values and distinguishes type annotations such as `password: SecretString = "..."`.
- Post-review hardening: Windows now rejects multi-hard-linked source files using safe open-handle metadata from `winapi-util`; Unix behavior is unchanged, and other non-Unix targets retain the trusted-root requirement.

RC29 intentionally leaves the separate release-validation gate unresolved, as requested: `Cargo.lock` generation, compilation, tests, Clippy, rustfmt, and MCP conformance still need to run in a Rust-enabled environment before release.
- 2026-08-16 follow-up hardening: multiline sensitive JSON/YAML/JS scalar values and YAML block scalars are redacted before model-visible output; explicit Authorization/Proxy-Authorization Basic/Bearer credentials are redacted regardless of credential length.
- 2026-08-16 follow-up hardening: Windows top-level searches are serialized and rebuild the RAM lexical index per request so same-size/same-mtime content replacement cannot be treated as a fresh cross-request index entry.
- 2026-08-17 protocol-state correction: modern 2026-07-28 requests are stateless and validated independently from each request's `_meta`; they do not bind the stdio process to Modern or get blocked by earlier legacy traffic. Legacy tool requests still require a successful schema-valid `initialize`, and the process retains only the boolean legacy-initialized compatibility state needed for subsequent metadata-free legacy requests. A legacy initialize can occur before or after modern requests without changing modern validation. Legacy version negotiation continues to respond with the single supported legacy revision rather than echoing an untested client revision; `server/discover` and unsupported-version errors now advertise both server-supported revisions (`2026-07-28` and `2025-11-25`), while only `2026-07-28` is accepted through modern per-request `_meta`.
- 2026-08-16 follow-up completeness hardening: paths removed by the pre-discovery policy filter (pruned/denied/binary/symlink entries, including pruned-directory sentinels) now contribute to `policy_excluded_files`, preventing absolute `NO_MATCH` when uninspected repository content exists.
- 2026-08-17 completeness follow-up: directories containing `.gitignore` or `.ignore` now contribute a conservative `policy_excluded` sentinel while ignore semantics remain enabled, so ignored content cannot yield an absolute repository-wide `NO_MATCH` without being inspected.
- 2026-08-17 redaction follow-up: when exact verification finds a query only in content removed by high-confidence secret redaction, search now returns a `[SIPPION_REDACTED_MATCH: ...]` existence marker instead of silently degrading to `NO_MATCH`; the secret value and source line remain suppressed.
- 2026-08-17 redaction follow-up: removed minimum-length exemptions from high-confidence sensitive literal assignments. Non-empty quoted and unquoted values such as `password="x"` and `token=abc` are now redacted regardless of length; empty values, structural `true`/`false`/`null`/`none` sentinels, and obvious computed references remain preserved. Added regression coverage for short literal credentials and preserved non-secret sentinel values.
- 2026-08-17 protocol follow-up: JSON-RPC/MCP request IDs now accept only strings or integers; fractional numeric IDs are rejected with `-32600 invalid request`, with regression coverage for the rejection path.
- 2026-08-17 Windows structural-cache follow-up: top-level `map_from_hits` calls are serialized on Windows and clear prior analysis/graph cache entries before reading candidates. This prevents same-size/same-mtime replacements from reusing stale symbols, semantic facts, graph edges, or centrality. Added a Windows regression test that seeds stale same-stamp analysis and graph entries and verifies fresh structure is rebuilt.

- 2026-08-17 multiline-redaction follow-up: sensitive keys embedded after underscore prefixes (for example `OPENAI_API_KEY`, `DATABASE_PASSWORD`, `AWS_SECRET_ACCESS_KEY`, and `SESSION_TOKEN`) now use the same boundary rule in multiline and YAML block-scalar detection as inline assignments, preventing newline-formatted literals from bypassing high-confidence redaction. Added regression coverage for prefixed multiline and block-scalar secrets.
- 2026-08-17 protocol-advertisement follow-up: `server/discover.supportedVersions` and `UnsupportedProtocolVersionError.data.supported` now enumerate both implemented protocol revisions (`2026-07-28` and `2025-11-25`). This changes advertisement only; modern request metadata remains restricted to `2026-07-28`, and legacy traffic still uses the legacy initialize flow.
